# concept-learning-material-generator

这个 Skill 用于把"想学一个概念"这件事，变成一份可以反复回看的、结构化的小型学习手册。

## 适用场景

调用时机：用户想要系统学习一个新概念、希望获得结构化、可复习、带自测的学习资料时使用。

典型场景：
- 自学一个新概念 / 预习 / 临时抱佛脚
- 教学前整理某个概念的知识手册
- 阅读到陌生术语想搞清楚它是什么、不是什么

不适合：
- 紧急的实战问题（直接给答案更高效，请改用 Ask 模式）
- 用户已经熟悉的概念（用一张脑图或简短回答即可）
- 需要长篇综述或学术论文级别的产出（请改用其他工具）

## 输入信息

AI 在执行此 Skill 前，应收集或假设以下输入：

- **`concept`**（必填，字符串）— 要学习的概念名称。建议中文为主，技术词中英对照。
- **`level`**（可选，默认 `intermediate`，枚举 `beginner` / `intermediate` / `advanced`）— 学习深度，决定内容展开的层级。
- **`focus`**（可选，默认 `balanced`，枚举 `mechanism` / `application` / `boundary` / `balanced`）— 关注重点，决定哪个章节展开最充分。
- **`audience`**（可选，默认 `general`）— 读者背景，例如 `data-scientist` / `frontend-dev` / `student`。会影响类比的选取。
- **`length`**（可选，默认 `standard`，枚举 `compact` / `standard` / `deep`）— 资料篇幅。

如果用户没有给出，可以按默认值处理，并在产出开头注明所做的假设。

## 生成步骤

1. **范围界定** — 用一句话明确"什么属于这个概念、什么不属于"，先把范围划清楚，避免后续偏题。
2. **结构化分解** — 把概念拆为 4–6 个可独立讲解的子主题（核心机制、组成组件、典型应用、边界条件、常见误区）。
3. **资料检索** — 调用 WebSearch / WebFetch 收集权威来源（官方文档、知名工程师或学者博客、近期综述）。**所有链接必须是可访问的真实 URL，不得编造。**
4. **个人化解释** — 避免堆砌术语。使用"如果你是 X，想解决 Y 问题"的代入写法，并在合适处给出类比。
5. **机制讲解** — 用分步描述 + 示意（SVG 或 Mermaid）展示内部组件如何交互。不要只画"一个个框"。
6. **应用案例** — 选 1–2 个端到端的具体场景，把每个子组件套进真实使用链路。
7. **混淆辨析** — 列出 2–4 组易混淆的对照（A vs B），说明区分关键。
8. **自测题** — 3–5 题，问题应能自我判分，答案折叠展示（`<details>`）。
9. **资料来源整理** — 末尾给出"参考资料"清单，包含 标题、URL、来源类型（官方 / 博客 / 论文 / 综述）、发布时间（如可得）。

## 输出结构

产出为**单文件 HTML**，使用语义化标签、内嵌 CSS（无外部依赖），阅读体验清晰：

```
<concept-slug>.html
├── 头部（标题 + 元信息：level/audience/length/生成时间）
├── § 1. 一句话定义
├── § 2. 学习目标
├── § 3. 核心问题
├── § 4. 个人理解（含类比）
├── § 5. 核心机制 / 组成
│   ├── 子组件清单
│   └── 流程图（SVG / Mermaid）
├── § 6. 一个具体应用场景（端到端）
├── § 7. 容易混淆的问题 / 使用边界
├── § 8. 自测题（<details> 折叠）
└── § 9. 参考资料（带 URL 和来源类型）
```

样式与排版要求：
- 中文为主，技术名词中英对照（如"上下文 / context"、"智能体 / agent"）。
- 段落首行不强制缩进，使用 section 标题层级。
- 流程图优先用内联 SVG；Mermaid 可作为备选并说明如何渲染。
- 自测题用 `<details><summary>` 折叠，避免一眼看到答案。
- 整体文件大小应 < 200KB。

## 资料来源要求

- 优先官方文档、权威综述、知名工程师或学者博客。
- 每条来源必须给出：标题 + URL + 来源类型 + 发布时间（如可得）。
- 不复述维基百科整段；如要引用 Wikipedia，请只引用作为入门指针。
- **严禁编造 URL、文档标题或论文**，无法核实的内容不要写。

## 自检要求（写完后逐条核对）

最终交付前必须自检并把清单写到 HTML 末尾或单独的"自检"小节：

- [ ] 是否包含个人化解释（不是纯名词堆砌）
- [ ] 是否覆盖核心机制或内部组成（不是只讲概念定义）
- [ ] 是否给出至少 1 个端到端可推理的应用场景
- [ ] 是否列出 ≥ 2 组易混淆对照或使用边界
- [ ] 是否包含 ≥ 3 个可自我判分的自测题
- [ ] 是否所有引用链接都真实可访问（用 WebFetch 抽样至少验证 2 条）
- [ ] 是否避免了过度术语堆砌（对目标读者友好）
- [ ] 篇幅与请求的 length 参数匹配
- [ ] 自检清单本身已粘贴到产物末尾

## 完成信号

每份 HTML 的最末应有一段"完成自检"：

> ✅ 已自检：本资料由 concept-learning-material-generator Skill 生成，所有引用链接已抽样验证可访问。
